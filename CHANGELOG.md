# Changelog

What changed for people who use PDT, newest first. Each section is compiled from the changelog fragments the pull
requests added (`.changes/`; docs/SDLC.md "Changelog") by `scripts/changelog.sh <version>`.

## 0.7.0 (2026-11-24)

### Added

- You and the PM can watch a document: the eye at the top of a document's page, or asking the PM. When it changes you hear what changed (the paragraphs, or a sheet's cells) and who edited it, once the edits stop for a few minutes, and new comments too. The "Document changed" workflow trigger now carries the change and who made it as well.
- A project setting lets agents create, edit and link documents without asking, on their own ticket or across the project; each change they make that way, with its diff, shows on the document and the agent's ticket.
- Download files from PDT, from your computer or your phone: a file from **Files**, a folder as a `.zip` (leaving out ignored files unless you ask for them), a ticket's attachments, and images in conversations.
- Inbox answers that act outside PDT ask for a second press, in any workflow: a choice that leads to a step acting outside PDT (posting a review or a comment, closing a pull request or an issue, Discord, Jira, a GitHub or Buildkite workflow run, an HTTP request that changes something), even through a condition or a wait, and Allow or Always allow on a tool that changes something outside PDT. Every answer waits five seconds with Undo before it goes out, and Recently answered lists your last answers and how you gave them.
- Agents can retry a single flaky CI job, a Buildkite step or a GitHub Actions job, instead of the whole build: only on the pull request's newest commit, at most twice per job, and each retry shows on the ticket's timeline. The Buildkite retry action can also retry chosen steps.
- Every PDT now has a name (Settings › This host › Name, and a new step in Get started), and another PDT can join one of your projects as a remote instance: pair it with a code from the project's **Remote instances** settings, and see its state, version, operating system, agents and free disk there. Work isn't sent to remote instances yet.
- A remote project's tickets can now run on a remote instance: label rules (or Start's Runs on) send a ticket there, its worktree and agents run on that machine, and you follow and answer them from the owner, under the ticket, marked "on <instance>".
- Terminals work on remote instances too: an agent started in its terminal, and any shell in a remote ticket's workspace, runs on that machine while you type, resize and scroll back from the owner. A new tab in a project with remote instances offers "Shell on <instance>", a shell in that instance's checkout of the project.
- A ticket running on a remote instance now has its runs and tests there too: you start and follow them from the owner, and a web run's Open link reaches it through that instance's remote access. Runs and tests can be limited to some systems with `os = "windows"` (or `"macos"`, `"linux"`, or a list) in `.pdt/project.toml`.
- A ticket running on a remote instance now has Files and Changes on the owner: browse, edit, search and download its files there, review its diff with comments and Approve, and see its conflicts with the base. Its changed files count in overlap checks, and Changes fetch the whole diff at once so a slower link stays quick.
- Auto-start fills each remote instance on its own, up to a cap you set for it on the owner (and one it can set for itself), and a ticket placed on an offline instance waits in To do with "waiting for win-box (offline)" until it is back, with a notification if it stays away for hours. Tickets no instance can run say what they need, and the "on win-box" mark shows when an instance is offline.
- Agents on a remote instance can use your secrets: each value is sent for one command or file and never kept there, and secrets you keep on that instance for the project win and never leave it. The owner's Updates settings list remote instances that need updating, with Update for each.
- Snooze any Inbox item until tomorrow, for a week, or until a ticket is done: it hides and comes back by itself, and the Inbox lists what's snoozed so you can bring it back sooner.
- Files can now open a project's checkout on each instance that joined it: pick **Repository** marked with the instance's name in the place picker to browse, edit, search and download its files.
- Projects on the local forge now work with remote instances: a ticket placed on one runs its CI there and merges into your base here, and a repository with no remote is copied to the remote instance over the link.
- A folder in Files has a download button on its row (shown when you point at it, always on touch screens), and a Download as .zip button at the top of the folder on a phone, so a folder can be downloaded without opening its menu.

### Changed

- Automatic workflow runs that had nothing to do are now kept for two days instead of 30, so the database stays much smaller; runs that did something or failed are still kept for 30 days.
- A ticket no longer merges or moves to Done while an agent's question about it waits in your Inbox: the ticket and its card say **Waiting on your answer**, and the Pipeline merges by itself once you answer. The question stays open even when the step that asked moves on, and agents can mark a question as only nice to have so it doesn't hold anything; you can still merge or close the ticket yourself.
- Dependabot's grouped updates with only patch and minor bumps now merge on green CI like single ones, and a pull request's review in the Inbox leads with its number, title and the reviewer's recommendation, asking you to confirm before you choose anything else.
- "Review outside pull requests" no longer asks you about a pull request whose only failing checks also fail on its base branch: it waits for the base (its run says "Waiting on main", with the ticket that looks like the fix), then brings the pull request up to date once the base passes, and your approval holds through that update as long as the pull request's own changes are the same. A new step note shows on a waiting run's row in Runs.
- A ticket's labels and areas show as chips with a **+ Add** button, its tab shows every stage by name, a parent shows its parts' progress and **Start next part** once, and the New ticket form puts Labels and Areas side by side. The peek's **Open** is now **Open in workspace**, and the ⋯ menu's **Refine** is **Refine with an agent…**.
- The board has the backlog's search and filters (priority, label, blocked, overlap), kept as you switch between Backlog and Board. With parent lanes, tickets that aren't parts sit under a "No parent" heading (hidden when there are none), and on a phone each parent's lane header fits on one row.
- On a phone, a ticket shows its stage once, as a button under the title: tap it to pick another stage. The details summary now names labels and areas, and "No priority" no longer has a dash in front.
- A persona's page is shorter and has one Save: its tools are a summary line with **Choose tools…**, which lists them by group with a search, and a bar at the bottom of the page appears whenever you have unsaved changes, with **Discard** and **Save new version**.
- Notes, Documents, Workflows, Personas and Files now share one list column: the same width, a title with **＋ New** at its top right (Workflows' Import and Export are under the **⋯** beside it), and the same empty page with a New button when nothing is open. On a phone the list no longer repeats the view's title under the top bar.
- Notes, documents, Markdown files, persona instructions and ticket descriptions all switch between viewing and editing with the same **Preview | Edit** control (Markdown files add **Source**). **Watch** is now a labelled bell button that reads **Watching** while you watch, and a document's **Watched by** sits in the line under its title.
- The Workflows list now shows full names: built-ins no longer carry a badge, off workflows say **Off**, and your own are marked **Yours**. A workflow with no runs offers a **Dry run**, and a built-in template lists its parameters as plain text.
- A document's page puts its project and ticket links as chips on the line under the title instead of a card above the content, and you rename it by clicking the title. The Documents list has one Filter menu, with the filters in force as chips you can clear, and a sheet's filter button reads "Filter by this cell" while the selected cell is empty.
- A new conversation is named after your first message, so the sidebar, tabs, command palette, Inbox and notifications tell your conversations apart instead of listing each by its project's name. A name you give it yourself stays.
- Approvals have the same buttons in the same order everywhere: **Allow**, **Always allow in this session**, then **Deny**, in a conversation, the Inbox and on a phone. An agent's own questions in the Inbox now work like PDT's: number keys pick a choice, **Send answers** sends them and **e** dismisses, and **n** never dismisses a question.
- Inbox rows now say which conversation, agent and project each question or approval comes from, and show long titles on two lines. Snoozed items open to be read, with Unsnooze at the top; the list's small buttons are full size on touch screens.
- The New tab button stays in sight however many tabs are open, with a fade showing the tab strip scrolls, and the Agents heading has a **+** too. A **Search** button at the top of the side rail opens the command palette, and workspace rows no longer show a tab count next to their state.
- A PM conversation's header has room for its title again: Rename, Reset… and Close… moved into a ⋯ menu, the extra New conversation button is gone (use + above the list), and the internal "PM v1" label no longer shows.
- An ended terminal has one Restart, in the bar at its foot, which now says when the session ended and its exit code. When nothing was kept from its terminal, the empty panel says so instead of staying blank.
- Tidier This host settings: the PM screen is titled PM, the instance name sits at the top of Remote access (empty with the host name greyed in until you pick one, and **Use host name** to go back), Get started's progress shows above Checks, and Storage shows each disk as a bar with its folders by name instead of a wall of paths.
- Settings › Plugins is shorter on a phone: the category buttons are gone (the list is already grouped by category), and plugins no longer show an On or Off badge next to their switch.
- Deleting a todo or clearing completed ones now waits a few seconds with Undo before it happens, and Clear deletes all the finished todos together or none of them.
- The docs on pdt.dev now describe the newest release, the one its Download buttons and install scripts install; features still on their way show up there once a release ships them.
- The website now matches what PDT does: which Linux installs have a tray icon, Devin among the agents, a Linux download for ARM (aarch64), a Features section for Documents, and a privacy note on remote access and remote projects.

### Fixed

- PDT no longer slows down as its history grows: the checks it runs every few seconds in the background now look up only what they need instead of reading through every past event and workflow run.
- Long conversations open at once on their latest messages instead of loading their whole history first, with earlier ones loading as you scroll up; going back to a conversation you just had open is instant, and opening one after PDT restarts no longer waits behind the others. A conversation that is slow to load shows what has arrived so far with a Retry, and never stays on the loading placeholder.
- A double-click in the Inbox answers one item, not the next one that slides into place.
- Updated the URL parsing library to a release that fixes a crash on deeply nested `blob:` URLs (RUSTSEC-2026-0592).
- A batch of Dependabot pull requests opened at once is now reviewed in full: a bot's pull requests count only toward the repository's hourly triage cap, not the per-author one.
- The one-command install on macOS now installs the app only when it is signed by Personal Dev Team's own Apple developer account, not by anyone's signature.
- PDT no longer makes a ticket's worktree when the repository's `.worktrees` folder is a symbolic link or leads outside the repository, so a cloned repository can't place files elsewhere on your disk, such as over your git settings.
- A secret you name like one PDT keeps for itself, such as `update-token`, now always gives commands your own value, and both values stay hidden.
- Agents now read the titles of tickets made from outside issues, outside pull requests' titles and their changed files' names marked as outside text, in ticket searches, the PM's overview, briefing and daily update, watched-ticket messages and pull request views, so a title can't pass itself off as an instruction.
- **Agents change documents without asking** no longer covers agents working from outside input, such as triage or a workflow run a new issue or a webhook started: their document changes always ask you first.
- Agents now read CI logs, ticket comments written by a workflow that an issue or webhook started, and a triage session's messages as outside text, marked as data and never instructions, so text an outsider wrote can't pass as instructions through them.
- On the local forge, `[push] remote` must now name one of the repository's own remotes: a URL or a path there is refused, and PDT pushes nothing when no remote by that name exists, so a project's config can't send your branches somewhere you didn't set up.
- Remote projects are safer to link: calls between linked instances no longer follow redirects, and a project's repository address goes to a remote instance without any username or token it holds.
- The page you land on after signing in to an MCP server or Google shows the service's reason for a failed sign-in only when it answers a sign-in you started, so a link from elsewhere can't put its own text on PDT's page.
- A closed terminal now frees its pseudo-terminal and memory at once, so a long-running PDT no longer runs the computer out of terminals for itself and every other app.
- Ticket views, the Inbox, notifications and workspaces stay quick on a long-used database: the lookups they repeat every few seconds no longer read through every past session, attempt and workflow run.
- Bug reports now take out this instance's name and the names and addresses of the instances it is linked with, and its remote projects' names, from the log excerpt they send.
- Watching documents no longer slows PDT down: large documents aren't re-read every few seconds, comparing versions runs in the background, and finished watches are cleaned up.
- Linked instances are held to the same rules as pairing: a project joined from another instance gets a valid project key, and a name, version or branch it sends that PDT can't use is refused instead of stored. Oversized answers from a linked instance are no longer read in full.
- A merge that fails because GitHub can't be reached or doesn't answer now says so as a service error, and a workflow run's Retry, Resume, Cancel or answer reports a missing run as not found and a change PDT couldn't save as a failed write, instead of all of them looking like a conflict.
- An error while handling a finished local CI run no longer stops PDT from reacting to later runs until it restarts, and the health check now lists the local CI watch.
- Starting a run or saving settings no longer waits while remote access is waiting on a slow or unresponsive Tailscale.
- PDT's memory use no longer creeps up over a long uptime: what it kept for deleted sessions, finished runs and ended tickets' pull requests is now let go, and removing a failed clone no longer holds up the app.
- When merging the base branch conflicts in a file that holds a code block (a Markdown file, say), the note to the agent now shows the conflict intact instead of breaking off at the file's own fence; Jira code blocks that hold a fence come through whole too.
- Failed CI logs from Buildkite and local CI now reach agents like GitHub's and GitLab's do: without terminal colour codes and timestamps, and cut to a manageable size when a line is huge.
- When an agent stops with an error, the message PDT shows no longer turns accented letters, emoji or other non-English text into `�` where they happened to arrive in two pieces.
- An open Google Doc no longer asks Google Drive for its comments every 2 seconds; PDT checks for new ones every 15 seconds instead, so it stays well inside Drive's limits.
- A long conversation no longer comes back blank after a reconnect (a laptop waking, the daemon restarting): it shows its latest messages, and earlier ones load as you scroll up without skipping any.
- The Inbox works from the keyboard and with a screen reader: after an answer, a snooze or an undo the focus moves to the item now showing, **u** undoes your last answer, the five seconds before an answer goes out stop while its Undo notice is hovered or focused, and "Press again to confirm" is read out.
- Keyboard focus stays nearby when a button removes itself: Show all in Snoozed and Recently answered, Unsnooze, Undo, Cancel code, Remove and Leave on remote instances and projects, Approve on a command, and removing the last watcher. An image that couldn't be attached now says why under the message box, not only on hover.
- The phone's tab overview reads every conversation's last line in one request, the workflow Runs list and Recently answered poll less often while nothing is running, a new pairing code no longer disappears for a few seconds after it shows, and commands an agent adds appear in Settings without a reload (approving them clears their Inbox item at once).
- The Inbox's small row buttons (Undo, Unsnooze, Mark all read) are now at least 24 pixels tall, so they are easier to hit with a mouse, and download links for attachments and images show a focus ring when reached with the keyboard.
- Remote instances and remote projects show "last seen" and similar times the way the rest of PDT does, and keep them current between refreshes. Empty lists, loading placeholders and errors across Files, Documents, the board, workflows and settings now look and behave the same everywhere, with Retry where a list fails to load.
- The backlog's Draft and Ready stage filter now shows as ticked, so ticking another stage adds to it, and the stage list has Backlog, All open and Show closed picks. The filter bar fits one row with Group and Sort menus, and once the filters change Clear and Save… show beside the ticket count; on a phone a line under Backlog and Board says which stages are shown and how many tickets match.
- A ticket's Conversation tab no longer tells you to start a ticket that is already in progress, a parent or closed. A ticket at work with no agent offers **Start an agent here** (or **Abandon…**), a parent lists its parts, and a closed ticket just says no agent worked on it.
- A Files link to a folder opens the folder even without a trailing slash, and a link to a file that's gone says so with a way back to its folder. On a phone an open file's name shows once, with its size and actions on one row.
- A conversation waiting for your approval now says "Waiting for you" instead of showing the command as running, and the bar over the message box appears only when the request is scrolled out of view, saying what the agent wants to do. Agent questions read "Question" rather than a tool name.
- The Add project dialog shows its four ways of adding a project (Folder, Clone a URL, Personal and Join a remote) as cards in a two-by-two grid, each with a one-line hint, so they no longer run together on narrow screens.
- Pairing a remote instance no longer hands out a code while remote access is off: Remote instances and Join a remote say so and link to the setting. The pairing code and address each have Copy, and Add instance sits in the section's header.
- Settings pages read better: an empty project Plugins section or All connections page now says what to do and opens Plugins, a section's buttons move under its description on a phone instead of squeezing it, and every Settings page has the same header.
- Settings › Secrets now says where values are actually kept, and warns when no keychain is available that secrets are lost when PDT stops. The agents' tool names moved into a "How agents use secrets" section you can open.
- An outside pull request with more than 1,000 files no longer keeps your Approve & merge across a later push: PDT can't read its whole diff, so it asks you again.
- Review outside pull requests: your Approve & merge no longer outlasts a close on GitHub (even if the pull request is reopened), your own Request changes in a review on GitHub, or 30 days; the next update is reviewed and asked about again.
- Snoozing a blocking question or a workflow's gate "until a ticket is done" no longer offers its own ticket, which can't be done until you answer it, and Snoozed says which items a ticket is waiting on.
- A snoozed waiting session or "Connect" notice in the Inbox no longer hides the next time it comes up: once the item goes away, its snooze goes with it.
- Review outside pull requests no longer fails when GitHub or CI is down for a few minutes: your Approve & merge still merges once CI passes, and a pull request waiting on its base branch asks you "Didn't merge" instead of being dropped.
- On GitLab, where retrying one CI job re-runs every failed job of the pipeline, an agent's retry now counts toward each of those jobs' two-retry limit, so no job is retried more than twice per commit.
- Removing a remote instance or leaving a remote project now says when the other PDT couldn't be reached, and a remote project its owner removed meanwhile shows **removed by its owner** instead of staying offline. Removing a project also revokes its remote instances' links and their keys; one that can't be reached shows the project as removed by its owner once it is back.
- A remote instance no longer shows as offline for a while after it restarts, and a login to an agent there now shows on the owner within a few minutes, or at once with **Check now**.
- Renaming an instance, or changing its remote access address, now reaches the instances it shares projects with instead of leaving them showing the old name or going offline for good. A pairing that is refused, such as an instance pairing with itself, no longer uses up the code.
- Approving a command in the Inbox now takes two presses and shows the command as it asks, Enter no longer approves it, and Undo takes it back for a few seconds, so a quick double press can't approve the next command unseen.
- An Inbox answer still waiting out its Undo seconds is no longer lost when PDT reloads itself after an update or you close the tab: the reload waits for it, and closing the tab sends it at once.
- In "Review outside pull requests", choosing Approve & merge after "Didn't merge" now waits for CI and watches the merge for as long as the first time, instead of asking "Didn't merge" again within seconds. A workflow step can now start its loop limits over, under When it fails.
- A change an agent made without asking to a Local document or sheet can now be undone: **Restore** on the change puts the document back as it was before it.
- A document's list of changes agents made without asking stays quick however many there are: it shows the newest 20 with **Show older changes** for the rest, and each change keeps at most 16 KB of its diff.
- Closing the tab of a stopped or interrupted agent session now asks first, as removing it does, instead of deleting its history straight away.
- Cloning a project by URL now shows git's progress and has a Cancel button that removes the partial clone. The clone finishes and the project is added even if you reload the page, and a clone that stalls for five minutes is stopped instead of spinning forever.
- Downloading a big folder as a .zip now shows "Preparing…" while PDT gathers its files, ignores repeat clicks meanwhile, and gives up quickly on a folder past the 2 GB or 200,000-file limit instead of reading through all of it.
- A conversation whose turn fails with an error that only sounds like a login problem (an MCP server that failed to authenticate, say) no longer says the agent isn't logged in: the error shows as it is and the conversation needs you, unless the agent's login check confirms it is logged out.
- With no agent installed, Start on a ticket and the PM now say so before you act, with a link to Get started, instead of failing afterwards with a program path; Start no longer leaves a branch and worktree behind when the agent is missing.
- Adding a project from a folder whose path you type or paste no longer stops on an empty Name: it takes the folder's name, as it does when you browse to it.
- On a phone, the website's screenshots are readable: they open on PDT's own phone view and show a close-up of each desktop screen, and the footer and docs links are easier to tap.
- The PM's watch list and the answers to its ticket edits now mark an imported issue's title as outside text, as its searches and overview already do, so wording in an issue's title can't pass for your instructions.
- Bug reports now also take out your remote projects' checkout folders, repository names, and worktree branches and folders from the log excerpt they send.
- A Claude or Devin session handed back from its terminal to the conversation shows as idle again, instead of sometimes showing no activity.
- Review outside pull requests asks you "Didn't merge" instead of failing when GitHub or CI is down while it waits for CI, sets a pull request to merge or watches the merge, or when CI is still running after 12 hours; after a review, it asks you as usual even when CI can't be read.
- Reloading a terminal whose process had ended now shows its last screen instead of a blank panel that kept saying "Reconnecting…".

## 0.6.4 (2026-11-16)

### Changed

- A question an agent asks while waiting for permission now shows the same cards as the Inbox's questions, with a description under each choice, tick boxes where several may be picked, and Something else… for your own answer.
- The Inbox's links name what they open the way they read ("PR #12", "PM session"), so voice control finds them, and its change sizes, error lines and the import dialog's keyboard hints look the same as elsewhere in the app.
- PDT opens faster: Settings, Setup, Files, the document and workflow import dialogs and the due-date picker now load the first time you open them, so the app's first load is about a sixth smaller.

### Fixed

- A request with a malformed query string, path or body now gets the API's usual JSON error, with a message saying what was wrong, instead of plain text.
- A workflow step's forge or CI error now names the service it came from (GitLab, Buildkite) instead of always saying GitHub, and every workflow step that lists a run's failed jobs writes them the same way, `workflow: job`.
- The Discord link shows as failed instead of connected when its connection stops unexpectedly, and odd values from Discord, Google, a forge's sign-in or an agent's rate limits no longer stop a background task or make PDT poll a forge in a tight loop.
- Approving a run's commands now shows them approved in Settings at once, opening an Inbox item clears its unread mark straight away, and a conversation's watch card stops saying "Watching" once the PM stops watching. The Link document dialog and a ticket's attachments no longer refresh every 2 seconds.
- The website's "Download for …" buttons download the file for your system (the Windows installer is now `pdt-windows-x64-setup.exe`) instead of opening the releases page. The one-line install no longer spends GitHub's hourly allowance of anonymous requests on a stable release, and a failed download says why, including when GitHub's rate limit is the cause.
- The install command for macOS and Linux now stops before downloading when it can't write to the folder it installs into, and on Linux asks about keeping PDT running after you log out only once. On a Linux desktop it says the tray icon comes with the AppImage, and the uninstall steps now also remove the version kept from the last update and say how to turn lingering off.
- Once you answer the PM's proposed Inbox decisions, its conversation keeps them as a card: each row with where its ticket went, the rows you unticked struck through, and any that failed with the reason.
- Toasts on a desktop now sit above an Inbox item's action bar and a conversation's composer instead of covering Deny or Send, and a "new approval" toast closes once you open the item it announces.
- The PM's Inbox decision card no longer reads "Decided 0 Inbox items" when the decisions were applied but their result isn't in the conversation; it says "Decided the Inbox items" instead.
- When an agent's login expires, its workflow steps wait instead of being nudged and reported as stalled: one Inbox item per agent says how to log in, new steps and auto-start wait too, and the steps go on by themselves once the agent is logged in again.
- PDT no longer reads an MCP server's reply without a size limit, so a misbehaving server can't make it run out of memory.
- Closing a PM conversation right as one of its replies finished could leave it running instead of ending it. Allowing the PM to move an outside ticket to To do now counts even when you click Allow the moment the request appears.
- A pull request or issue with very long text no longer makes its review or triage fail: the text is shortened, with a link to the rest. In Review outside pull requests, a review that fails now asks in the Inbox with Retry review, and a pull request set to merge is watched until it merges, so one the merge queue drops asks "Didn't merge".
- When an agent's run or test waits on a command you haven't approved, the Inbox now shows the command with Approve, and the project's Commands settings list the commands waiting in its worktrees, under their ticket and branch.
- A Claude agent asking to make or change a document, or for any other approval, now waits until you answer in the Inbox or its conversation, instead of giving up after five minutes while the request still showed.

## 0.6.3 (2026-11-08)

### Changed

- Approval cards now show what every one of PDT's asking tools would do: the issue, bug report, comment, document edit, issue link, command or file with secrets, in full, and a ticket's whole new description. A ticket named by id shows its key and title, and a call without a preview shows its arguments open, in the conversation and in the Inbox.
- Ticket keys look the same everywhere, and in an Inbox item's header, the PM's batch of decisions and the document import dialog they open the ticket and show its card on hover. A ticket's stage and labels look the same in conversation cards, the Inbox and the hover card.
- Links to the PDT website now show a preview picture when shared, each docs page has its own summary in search results, a missing page shows a proper "page not found" with links back, and the troubleshooting and contributing pages have shorter addresses (the old ones still work).
- The docs now have a page on Todos, explain **Make ticket…** in a chat, list workflow steps by the groups **Add node** shows, and match the Updates troubleshooting to what the **Version** row says.
- A workflow's Runs tab leaves out the runs that ended with "Nothing to do", so the runs that did something are easy to find. Turn on "Show “Nothing to do” runs" above the list to see them.

### Fixed

- When PDT itself fails (its database or the keychain) while importing or linking a Jira issue, signing in to Google or reading a Google document, it now says so in plain words instead of showing the database's or keychain's own text or blaming Jira or Google. A Google sign-in PDT can't read from the keychain no longer tells you to remove PDT's access in your Google account.
- The reason you give when you deny an agent's call in the Inbox now reaches the agent, as it already did from the conversation.
- Google sign-in is harder to misuse: going back to a PDT that isn't on this computer takes typing its address, signing an account in as a different Google account stops agents acting as the old one, and PDT no longer folds an OAuth client's other Google permissions into its own.
- A PM on Codex, Devin or Bypass can move a ticket from outside PDT onto the board again where the project lets the PM act: it asks for your Allow instead of failing. An approval says when its call holds a secret's value, **Always allow in this session** now covers one project only, and an Allow given after the agent stopped waiting no longer runs a tool the agent has lost since.
- An agent other than the PM can stop another ticket's work only when it names that ticket by its exact key, as for edits, and the ticket's timeline now says which agent stopped it instead of always naming the PM.
- An image written as `//site/picture.png` in a ticket, document or conversation now waits for **Load image** like any other image from another site. A sheet exported as CSV puts a `'` before text that starts with `=`, `+`, `-` or `@`, so opening the file in Excel never runs it as a formula.
- Updates are now downloaded only over https and unpacked into a private folder of their own, and release tags with unusual characters are ignored. Pull request comments, reviews and files are read page by page only from your forge's own address, so the sign-in token is never sent anywhere else.
- Opening a ticket with linked issues no longer reloads every ticket list, and renaming, linking or removing a document no longer reads open documents again from Google Drive or another provider. A provider search is no longer repeated when the window regains focus.
- The website's screenshots show the current app, including the Inbox's recommended answers, and the landing page now says to log in to Claude Code by running `claude` and typing `/login`, as the docs do.
- A reset PM conversation now shows the PM's own introduction and "Ask the PM…" prompt, like a new one, instead of a generic agent prompt with PDT's data folder.
- When PDT's host stops answering, sections that can't load and failed actions now say "Can't reach PDT: it isn't answering." instead of the browser's "Failed to fetch".

- A new built-in workflow, "Cut a release" (off by default), lets the PM start a release when you ask for one: it opens the release pull request, puts it in your Inbox for review, and tells you when the release is published.
- The PM can run one of your enabled workflows when you ask, after you confirm it, such as "Cut a release" with the kind of version bump you want.
- PDT runs on Linux (x86_64 and arm64): a headless tarball that `pdt-host install` sets up as a systemd user service, and an AppImage for desktops. Both update themselves like the macOS and Windows apps, and on machines without a system keyring secrets are kept in a file in the data folder that only you can read (Settings → Secrets says which).
- Text from outside PDT (issue titles and bodies, webhooks, imported tickets' descriptions) now reaches agents fenced off as data, never instructions; comments and reviews from people who aren't collaborators on the repository stay on the ticket's timeline instead of going to the agent. Triage is capped per author and per repository an hour (Settings → Host), and the ticket's timeline records each time outside input reached an agent.
- The PM's conversation list puts a dot on a conversation that has replied while you were elsewhere, and a spinner on one that is working; the dot goes once you open it.
- Experimental releases: builds of main published by hand as pre-releases between stable releases. Set Settings → Updates → Update channel to experimental to get them (they can carry database changes no stable release has yet, so such a host stays on them until a newer stable release ships); the update banner and Settings mark them "Experimental". Ask the PM for an experimental release, or run "Cut a release" with channel experimental.

### Changed

- Updates now come only from deliberate releases with SemVer versions (the next is 0.2.0), not from every merge, and an older release is never installed over a newer one. When an update is available, Release notes show the notes of every release between your version and the new one.
- PDT has a new logo, a lowercase "pdt" with a blue underline. It is the browser tab's icon, the app and installer icon, and the tray icon. On macOS the menu bar shows it in black or white to match the bar.
- A new Pipeline accepts tickets labelled `agentic` automatically: once QA passes they merge without waiting for you at Accept. Pipelines you already have keep their own list of labels.
- In a PM conversation, PDT's daily update and its checkpoint and journal requests now show as one muted line ("PDT brought this conversation up to date · 1d ago") that you can open to read in full. The daily update itself is shorter: one line per ticket that changed, no schedule or overlap noise, only what other conversations' journals leave open, and on a quiet day just a checkpoint request or nothing.
- A release you start (or ask the PM for) now ships by itself: its release PR merges once its checks pass, with no review step. "Cut a release" tells you when the PR is open and when the release is out, and puts a failed check in your Inbox with the failed jobs, so you can push a fix or close the PR. To change the release notes, edit the changelog fragments before starting the release.
- Auto-start now takes the most urgent ticket first (urgent, high, medium, low, none), then backlog rank, so a high-priority ticket no longer waits behind a lower one ranked above it. To keep the old order, set the project's "Auto-start picks by" to Backlog rank. To do tickets still come before Ready ones.

### Fixed

- Cancelling a workflow run no longer lets its agent step's session start up again: a nudge PDT had queued for it could reopen the stopped conversation a moment after the cancel.
- Agents can no longer let a ticket from outside PDT (an issue or a report) in by calling PDT's HTTP API themselves: moving it to To do, starting it, labelling it `agentic` or approving the PM's move of it now only works from PDT's own window.
- Opening an Inbox item on a phone no longer leaves a blank screen when PDT was updated since the page loaded: it reloads into the new version. A view that fails to show now says "Something went wrong" with Reload and Back to Inbox instead of a blank page.
- When GitHub stops accepting PDT's login (a revoked or expired token), the Inbox now says "Reconnect GitHub" and Settings › This host › GitHub shows it with a Reconnect button; PDT stops calling GitHub until you connect again, then picks pull requests and CI back up at once.
- Check for updates and Settings no longer say the update token can't be read because macOS "may be waiting for someone to allow access" when there is no prompt: keychain reads no longer fail just because another one is in progress, and PDT remembers what it read instead of asking the keychain on every check. A real keychain timeout now names the secret it was reading.

## 0.1.x: continuous builds

Every merge to main published a release, `v0.1.<build number>`, which the stable app installed when idle or on
Update. Those releases had no changelog: each one's notes were the merged pull request's title and description, and
the app's Release notes listed the tickets each update brought.
