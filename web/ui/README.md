# web/ui — PDT's component library

## Layout

- `tokens.css` — every colour and token (`--pdt-*`), light and dark. The only place colours are defined.
- `shadcn.css` — shadcn's animations and `data-*` variants (copied from the shadcn package).
- `primitives/` — shadcn/ui components (React Aria base, Nova style), generated by
  `pnpm dlx shadcn@latest add <name> -y -o -c web < /dev/null` (without those it can hang on an overwrite prompt) and then edited to fit. Ours to change. **Features never import these.**
- `lib/` — helpers for the primitives (`cn` in `lib/utils`).
- `<Name>.tsx` — the public components (our API), built on the primitives. `index.ts` exports them; features import
  everything from `@ui`. The one exception is `FlowGraph` (React Flow, for the workflow builder): features import it
  as `@ui/FlowGraph` so it and its styles load only with the builder's lazy chunk. Only web/ui imports `@xyflow/react`.
- `<Name>.test.tsx` — a test per public component.
- Gallery sections: `web/src/gallery/sections/<group>.tsx` (see "Gallery").

## Styling rules

- Colours only through these Tailwind names (all aliases of `--pdt-*`):
  - surfaces: `bg-background` (= `bg-bg`), `bg-card`/`bg-popover` (= `bg-surface`), `bg-surface-2`, `bg-muted` (a quiet fill), `bg-band`
    (striped list rows), `bg-accent` (the soft selected/hover fill), `bg-primary` (accent blue, primary actions);
  - text: `text-foreground` (= `text-fg`), `text-muted-foreground` (secondary text), `text-link` (accent-coloured text and icons: links, ticks; never
    `text-primary`, which is the fill colour and too light for text),
    `text-primary-foreground` (on `bg-primary`), `text-destructive`;
  - lines: `border-border` (dividers, cards), `border-input` (control edges: fields, checkboxes, outline buttons, the off switch), `ring-ring`;
  - status (state only, never decoration): `running`, `waiting`, `failed`, `idle`, and fills `running-soft`,
    `waiting-soft`, `failed-soft`; diff: `diff-add`, `diff-del`, `diff-add-strong`, `diff-del-strong`;
  - overlays: `bg-backdrop`; shadows `shadow-popover`, `shadow-dialog`, `shadow-card` (cards on the page; none in dark).
- No raw colours (hex, rgb, `bg-black/…`, `ring-white`, Tailwind's palette such as `bg-red-500`), no Tailwind shadow
  scale (`shadow-sm`…`shadow-2xl`), no arbitrary type sizes (`text-[13px]`, `text-[0.8rem]`), no `z-[…]`; hover fills
  are `hover:bg-accent`. Type sizes: `text-2xs` (10px
  labels), `text-meta` (11px secondary lines), `text-xs` (12), `text-sm` (14), `text-base` (16), `text-heading` (18px, a page's or document's title: settings pages, documents, todos), and
  `text-title` (30px, a note's title). Never `text-lg`, `text-xl` or larger. Layers:
  `z-(--pdt-z-sticky)` (sticky headers inside a scrolling pane), `z-(--pdt-z-popover)`, `z-(--pdt-z-dialog)`, `z-(--pdt-z-menu)`, `z-(--pdt-z-toast)`. A test (`src/lint.test.ts`)
  enforces this outside `tokens.css`.
- Sizes: controls are `h-control-sm` (24px) or `h-control-md` (28px, the default); on touch screens
  `pointer-coarse:h-control-touch` (44px) / `pointer-coarse:min-w-control-touch` for icon buttons. `h-control-lg`
  (48px) is the large touch button (`Button size="lg"`). Corners follow `--radius`
  (6px): `rounded-md` (0.8 × radius, about 5px: controls), `rounded-lg` (the radius: cards, toolbars).
- Gutters: page-like content (settings pages, the Inbox, a conversation, a ticket) pads its sides with `px-gutter` /
  `p-gutter` (16px, 24px from `sm`). A view whose content sits on the gutter gives its `ViewHeader` `gutter` (and its
  tab bar `px-gutter`) so header and content line up; terminals, lists and boards keep the header's tight 12px. Reading content is `max-w-3xl`: left-aligned on pages, settings and the Inbox, centred
  in a conversation; a ticket is `max-w-6xl`, centred.
- Dimming: disabled controls use `opacity-50`, and nothing else is dimmed with opacity. A state such as cleared, skipped
  or not built shows as muted text, a dashed edge or a badge, so its text keeps 4.5:1 (tokens.test.ts checks the token pairs).
- Dark mode: `dark:` follows our theme rule; usually no `dark:` is needed because the tokens switch.
- Motion: `duration-(--pdt-duration)` / default transition duration; nothing animates under
  `motion-reduce`. Anything that animates, transforms or transitions layout says `motion-reduce:animate-none` /
  `motion-reduce:transition-none` in the same class string (`src/lint.test.ts` checks); `src/index.css` also cuts
  every animation and transition to near zero under reduced motion, as a safety net.

## Component rules

- **Familiar props.** Public components accept the props features already use: `onClick` (mapped to React Aria's
  `onPress`), `disabled` (→ `isDisabled`), `type`, `title`, `aria-*`, `className` (appended last). Keep the old
  `Button` API working (`variant` primary | secondary | ghost; adds danger; `size` sm | md; `pending`).
- **Accessible by default.** Real roles; icon-only controls require a `label`; every overlay closes on Escape and
  returns focus to what opened it; Up/Down/Home/End in lists and menus; long press = right-click on touch.
  Features build overlays from `Dialog`, `Sheet`, `Popover`, `Menu`, `Select` and `Tooltip`, never a hand-made
  `role="dialog|menu|listbox|tooltip"` (a test fails on one); a `Sheet` can open from a `Dialog`.
  A page's sections are `Tabs` with a `TabPanel` per tab (put the panels straight inside `Tabs`: what sits between
  renders twice, once to collect the tabs). Only editor-style tabs that are dragged, renamed or closed (a workspace's
  tabs, the documents beside a page) are a hand-built `role="tablist"`: `onKeyDown={tabListKeyDown}`, tabs with
  `tabIndexOf(…)` (Left/Right/Home/End, one Tab stop), and a `role="tabpanel"` labelled by the tab's id.
- **Use the piece that exists.** Something folded away is a `Disclosure` (`inline`: a muted line such as "Show the
  comments"; `row`: a folding section or nav group), never `<details>` or a hand-made chevron button. A card to pick is
  a `ChoiceCard` (`selection="current"` for the card of what's on screen), one of a few options in a form a
  `ChoiceCardGroup`. The small uppercase label over a group is a `SectionLabel`, a side list's group heading a
  `ListHeading` (its ＋ button in `trailing`). A count is a `Badge count` (`tone="solid"` for what waits on the user,
  `size="sm"` on an icon or in a chip). A phone screen's big bottom buttons are `Button size="lg"` (48px,
  `h-control-lg`); a touch-sized control written by hand is `h-control-touch`/`size-control-touch`, never `h-11`.
- **Touch.** Long press opens the same menu as right-click (`MenuTrigger trigger="contextMenu"`). Drag data is
  `text/plain` with a `pdt:<kind>:<id>` value (Android Chrome drops custom types); draggable rows carry a
  `<Button slot="drag">` handle. Sheets open from a button, never an edge swipe. Never make a long-press target natively `draggable` on touch
  screens (Android turns the long press into a drag): drag from a handle, or only with a fine pointer.
- **Pending and errors.** Actions show `pending` on their control; forms show errors with `Alert`/`Field`; everything
  else toasts (`toast.error(message)`).
- **Times.** `lib/time.ts` (exported from `@ui`) is the one home for time formats: `relativeTime`, `shortAge`,
  `shortDate`, `absoluteTime` (tooltips), `clockTime` and `formatDuration`. In render, show a relative time with
  `<RelativeTime>` (it ticks every minute; `short` for a list row's "2h"), never `relativeTime()`, whose text goes stale.
  Counts, capitals and byte sizes are in `web/src/common/text.ts` (`plural`, `capitalize`, `formatBytes`).
- **Dates.** `Calendar` (a month to pick a day from: Monday first, ‹ › to page, arrows move, Enter picks) takes and
  gives plain `YYYY-MM-DD` strings; `min` makes earlier days unpickable (except the chosen one), today is amber with a
  dot, the chosen day `bg-primary`. Its primitive (`primitives/calendar.tsx`) is written by hand on React Aria's
  `Calendar`/`CalendarGrid`/`CalendarCell` with `@internationalized/date`: `shadcn add calendar` would overwrite our
  edited button, input, input-group, select and textarea primitives.
- **Checkbox shapes.** `Checkbox shape="round"` is the todo list's 18px circle: a muted border (`danger` makes it
  red), filled `running` green with a dark check when ticked. The square default is for forms and lists.

## Settings pages

Every settings page (host, project, and whatever comes next) is built the same way from `Section` and `SettingsRow`,
so a page reads the same everywhere and nothing destructive sits next to something routine:

- **One section per screen (PDT-231).** A page's sections are each a screen of their own, with a path
  (`/settings/host/<slug>`, `/settings/projects/<KEY>/<slug>`), listed in the Settings sidebar (whose search matches
  section names and the settings on them: `web/src/common/settingsSections.ts`). `SettingsScreens` (web/src/common)
  shows one in a `SettingsScreen`: a breadcrumb, then the `Section` whose label is the screen's `lead`, whose heading
  and description become the screen's title. More cards on the same screen (Agents' Programs) are `Section`s too,
  under their own small headings. A single-screen page (Notifications, Secrets) is a `Page`.
- **Section cards → rows.** A `Section` is a heading (and description) over a bordered card; each child of the card
  is a row, divided from the next. Group by what the user is configuring, not by API field.
- **One setting per row.** `SettingsRow`: label (and a one-line description) on the left, the control on the right.
  `stacked` for wide controls (text areas, file views, folder fields). State goes in a `Badge`/`StatusDot` in the
  row (Active, Stored, Expired, Found, `env`), not in prose.
- **Saving: as you change (PDT-231).** Nothing has a Save button: a switch or select saves at once, text on blur or
  Enter (`AutoSaveText`; Ctrl/⌘+Enter in a text area), and each shows "Saved ✓" beside it for a moment, or its error
  (`AutoSaveRow`, `SaveStatus`, `useSaveState` in web/src/common/AutoSave.tsx). A failed save keeps the typed text;
  Escape puts the stored value back. Only secrets and tokens, raw TOML (a project's host overrides) and the Danger
  zone keep an explicit button. A setting the environment overrides shows an `env` badge and is read-only.
- **Phones.** Below `md` a page's own path lists its sections; each is a screen of its own. Text fields and selects
  in a row take its full width.
- **Buttons are buttons.** In settings every action is a bordered `secondary` button (or `primary` for Save);
  `ghost` is for toolbars, and `Link` is only for navigating somewhere (a URL, another page), never for an action.
  Section-wide actions that change nothing (Check for updates, Run checks again) go in the section's `actions`.
- **Destructive actions live in the Danger zone.** Page-wide removals (remove the project, remove the token) go in
  a `Section danger` at the bottom of the page, as `danger` buttons whose label ends in "…" and that confirm;
  removing a project also asks for its name to be typed (`typeToConfirm`). The one exception is a per-item removal inside a list (a worktree): a secondary button with a trash
  icon, still "…" and confirmed. Never put a destructive button beside a routine one.

## Tests

- Vitest + Testing Library + user-event (`pnpm --dir web exec vitest run ui/<Name>.test.tsx`). Query by role and
  name. Cover: rendering of each variant that changes behaviour, keyboard (open, move, select, Escape), focus
  return, and the touch path where it applies (long press: `fireEvent.pointerDown(el, { pointerType: 'touch' })`,
  advance fake timers past 500ms, `pointerUp`).
- jsdom has no layout: don't assert positions.

## Gallery

`/gallery.html` (dev server only) shows every component. Each group of components adds one file
`web/src/gallery/sections/<group>.tsx` exporting:

```tsx
export const section = { title: 'Buttons', order: 10, render: () => <>…every variant…</> };
```

The gallery picks up every file in that folder by itself (`import.meta.glob`).
