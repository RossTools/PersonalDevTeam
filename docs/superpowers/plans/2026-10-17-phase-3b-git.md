# Phase 3b — Git integration: plan

Spec: docs/superpowers/specs/2026-10-17-workspaces-design.md §6. Branch `phase-3b-git`.

**Decisions made while planning** (the spec is updated to match):
- The sidebar has no project tree since 3a, so worktree actions and GitHub links live on each project's page in
  Settings; session and run headers link their branch. Runs record no commit, so there are no commit links.
- Cloning blocks until git finishes (the form shows "Cloning…") instead of streaming progress, and runs with
  `GIT_TERMINAL_PROMPT=0` so a credential prompt fails instead of hanging.
- Keys for existing projects are filled in by pdtd when the store opens (initials need Rust, not SQL).

## Backend (TDD)
1. **pdt-core:** `project::valid_key`, `suggest_key(name, taken)`; `Project.key`, `Project.github_repo` (API-only,
   from `origin`), `NewProject.key`, `ProjectPatch {name?, key?}`, `CloneProject {url, parentDir?, name?, key?}`;
   `git_url::repo_name(url)`, `git_url::github_repo(url)`; `Worktree.missing` (API-only); `HostSettings.projects_dir`.
2. **pdt-git:** `clone(url, dest)`, `remote_url(repo, name)`, `list_worktrees(repo)`, `is_dirty(dir)`,
   `remove_worktree(repo, path, force)`, `delete_branch(repo, branch)`, `prune_worktrees(repo)`,
   `list_files(checkout, dir)` (`ls-files -co --exclude-standard`), `status(checkout, dir)`.
3. **pdt-store:** migration `0009_project_keys.sql` (`key` column, unique index); backfill missing keys on open;
   `update_project`, `delete_project`, `delete_worktree`.
4. **pdt-api:**
   - `POST /api/projects` takes `key`; `PATCH /api/projects/{id}`; `DELETE /api/projects/{id}` (stops sessions and
     runs, never touches files); `POST /api/projects/clone`.
   - Projects carry `githubRepo`; worktrees carry `missing`.
   - Adopt an existing `.worktrees/<branch>` worktree in worktree create and in run start.
   - `DELETE /api/worktrees/{id}?force=&deleteBranch=`: `409 worktree_busy` (running sessions/active runs),
     `409 worktree_dirty` (uncommitted changes, without `force`); a missing worktree is just forgotten.
   - `GET /api/projects/{id}/files?worktreeId=&path=`, `GET …/files/content?worktreeId=&path=`: contained paths only
     (`400 path_outside`), `413 file_too_large` over 1 MB, binary flagged.

## Web
5. Settings project page: key and name editing, GitHub link, worktrees list (branch link, Open PR, Remove with
   uncommitted-changes confirmation and a delete-branch checkbox, Forget for missing), Remove project.
6. Add project: by path or clone by URL (folder defaults to the Projects folder host setting); key field with
   suggestion. Host settings: Projects folder.
7. Keys in the sidebar's workspace rows and the Settings project list.
8. Files view (rail): place picker, file tree (lazy directories, git status letters), CodeMirror read-only viewer
   with language by file name and token-based colours.
9. Docs, checks, PR.
